# 《空洞骑士：丝之歌》Unity 工程学习计划

## 1. 学习目标

目标不是通读所有反编译 C#，而是把一个完整的商业 2D 游戏工程拆成可理解、可验证、可复现的系统。

第一里程碑是完整学会启动链和首个可玩场景 `Tut_01`：

1. 能解释游戏如何从启动场景进入标题、开场和 `Tut_01`。
2. 能画出 `Tut_01` 的场景骨架、相机区域、出生点、出口和主要交互。
3. 能追踪输入到角色移动、动画、物理和音效的完整调用链。
4. 能追踪一次攻击从判定到敌人受伤、硬直、死亡和反馈的完整调用链。
5. 能解释场景的精灵分层、材质、Shader、粒子、环境动画和后处理。
6. 能在独立学习场景中复现一个简化房间，而不是复制原工程对象。
7. 能把同一套分析方法应用到 `Tut_01b`、`Tut_02` 和后续区域。

建议总周期为 12～16 周，每周 8～10 小时。时间不足时按阶段完成，不按日历赶进度。

## 2. 工程事实与学习起点

| 对象 | GameObject | MonoBehaviour | SpriteRenderer | Animator | 结论 |
| --- | ---: | ---: | ---: | ---: | --- |
| `Pre_Menu_Loader` | 2 | 1 | 0 | 0 | 最小启动入口，先学 |
| `Pre_Menu_Intro` | 15 | 11 | 8 | 1 | 第一个小而完整的视听场景 |
| `Opening_Sequence` | 72 | 86 | 45 | 3 | 适合学习演出和切场景 |
| `Menu_Title` | 4,663 | 7,280 | 740 | 680 | 初期只追踪主流程，不展开全部对象 |
| `Tut_01` | 3,552 | 1,174 | 2,694 | 27 | 第一个完整可玩场景，按系统拆解 |
| `Hero_Hornet` Prefab | 703 | 1,218 | - | 60 | 不整棵阅读，只研究当前动作所需分支 |

真实的新游戏主流程是：

```text
Pre_Menu_Loader
  -> Addressables: Scenes/Pre_Menu_Intro
  -> Menu_Title
  -> Opening_Sequence
  -> Tut_01
  -> Tut_01b / Tut_02 / 后续场景
```

注意：反编译工程中仍存在《空洞骑士》的旧数据和旧名称，例如 `Tutorial_01`、`Town` 以及旧版 `WorldNavigation` 条目。判断当前丝之歌逻辑时采用以下证据优先级：

```text
实际运行结果
  > 当前场景和 Prefab 的序列化引用
  > Addressables 配置
  > 当前调用路径
  > 常量名、生成代码和疑似旧数据
```

不要因为某个类名或常量存在，就默认它一定参与当前游戏流程。

## 3. 固定学习方法

每个场景和系统都按同一个循环学习：

1. **观察**：实际运行，只记录看到的事件和时间顺序。
2. **定位**：在 Hierarchy 中找到负责对象，记录组件和关键 Inspector 参数。
3. **追踪**：从触发源追到结果，最多先追一条主调用链。
4. **实验**：一次只改一个非破坏性参数，预测结果后再运行验证。
5. **复现**：在独立的 `LearningLab` 场景中用简化对象重做机制。
6. **总结**：画一张图、写一页笔记、列出仍不确定的地方。

每次学习只回答一个具体问题，例如：

- Hornet 按下跳跃键后，哪段代码设置竖直速度？
- `CameraLockArea` 如何改变相机边界？
- 一次攻击如何生成命中、伤害、击退、闪白和音效？
- 进入 `Tut_01b` 前，哪些玩家数据会被保存？

禁止使用“今天读懂 `HeroController.cs`”这类没有边界的目标。

## 4. 分阶段路线

### 阶段 0：建立安全的学习环境（半周）

学习内容：

- 确认 Unity 版本、启动场景、Addressables 和当前可运行基线。
- 建立只用于实验的 `LearningLab` 场景和笔记目录。
- 学会用 Git 查看单次实验改动，避免误改恢复工程的大型场景和 Prefab。
- 记录编译警告、缺失资源、Dummy Shader 和反编译代码失真等已知限制。

产出：

- 一份运行基线记录：启动是否成功、首场景是否可进入、当前主要错误。
- 一张工程顶层地图：Scenes、Prefabs、Scripts、Materials、Shaders、Audio、Addressables。

完成标准：

- 能从 `Pre_Menu_Loader` 启动并说明为什么 Build Settings 只需要这个入口。
- 能恢复一次实验性改动，且不会覆盖其他已有修改。

### 阶段 1：启动与加载链（第 1 周）

研究对象：

- `Assets/Scenes/Pre_Menu_Loader.unity`
- `Assets/Scenes/Pre_Menu_Intro.unity`
- `Assets/Scripts/ProjectCode/Game/00_Bootstrap`
- Addressables 场景组
- `StartManager`、场景加载和淡入淡出相关组件

学习主题：

- Unity 生命周期：`Awake`、`OnEnable`、`Start`、协程。
- Addressables 异步加载。
- 启动相机、Logo、文字、音频、加载动画和淡入淡出。
- 全局对象何时创建，哪些对象跨场景保留。

实践任务：

- 画出 `Pre_Menu_Loader -> Pre_Menu_Intro` 的时序图。
- 在 `LearningLab` 中复现“加载提示 -> 异步加载 -> 淡出 -> 切换场景”。

完成标准：

- 不看代码也能先口述启动顺序，再用代码和 Inspector 逐项证明。

### 阶段 2：开场演出与进入世界（第 2 周）

研究对象：

- `Assets/Scenes/Opening_Sequence.unity`
- `OpeningSequence.cs`
- 演出序列、Animator、粒子、音频循环、文字和场景切换组件

学习主题：

- 演出时间线和 Chain Sequence 的组织方式。
- 动画事件、协程、跳过演出和完成回调。
- 音乐、环境声、淡黑、粒子和镜头如何同步。
- 新游戏为什么最终进入 `Tut_01`。

实践任务：

- 把开场拆成“触发—持续—完成—切场景”四列事件表。
- 复现一个 10～15 秒、可跳过、结束后切场景的简化演出。

完成标准：

- 能从 `GameManager.StartNewGame()` 一路追踪到 `Opening_Sequence`，再追踪到 `Tut_01`。

### 阶段 3：`Tut_01` 场景骨架（第 3～4 周）

第一遍只看结构，不读角色和敌人内部实现。

研究对象：

- `_SceneManager`
- `_Transition Gates`
- `Death Respawn Marker Init`
- `Hazard Respawn Marker`
- `CameraLockArea`
- `Hero Detector`
- `Music Region Initial`
- `Audio Snapshot Region`
- 地形、碰撞层、前景、中景、背景和交互对象分组

学习主题：

- 场景根节点和功能分区。
- Layer、Tag、Sorting Layer、Z 深度和碰撞矩阵。
- 出生、危险重生、场景出口和相机边界。
- Trigger 如何启用教程、敌人、镜头或音频。

实践任务：

- 绘制 `Tut_01` 房间路线图，标出出生点、危险点、相机区域、敌人、教学触发器和出口。
- 在副本或临时实验中逐组隐藏“背景、前景、粒子、敌人、交互”，观察每组职责。
- 为一个入口建立事件链：

```text
进入 Trigger
  -> 激活条件
  -> 相机/敌人/提示发生变化
  -> 写入状态
  -> 恢复或结束
```

完成标准：

- 能在 10 分钟内向别人讲清 `Tut_01` 的空间结构和主要功能区。
- 能从任意一个相机区域或出口定位到负责的对象和脚本。

### 阶段 4：渲染与场景美术（第 5～6 周）

研究内容：

- SpriteRenderer、Sorting Layer、Order、Z 深度。
- 精灵图集、材质和 Shader。
- 多层背景、前景遮挡、雾、光、瀑布、植被和骨骼场景装饰。
- 粒子系统、环境动画、颜色分级、相机后处理和宽屏遮罩。
- 恢复工程中的 Dummy Shader 与原版视觉差异。

实践任务：

- 选取 `Tut_01` 的一个屏幕区域，列出从后到前的渲染层。
- 各关闭一次材质、粒子、后处理和前景遮挡，记录画面差异。
- 在 `LearningLab` 复现一个具有背景、中景、可碰撞地形、前景、环境粒子和相机后处理的房间。

完成标准：

- 遇到黑块、透明错误或全屏异常时，能判断是贴图、材质、Shader、排序、相机还是 RenderTexture 链路。

### 阶段 5：Hornet 基础移动与动画（第 7～8 周）

不要从头通读 283 KB 的 `HeroController.cs`，也不要展开拥有 703 个对象的完整 Prefab。只追踪 `Tut_01` 当下允许的基础动作。

建议顺序：

1. 输入采样。
2. 左右移动与朝向。
3. 跳跃、下落和落地。
4. 墙体、斜坡、边缘和地面检测。
5. 冲刺或场景初期已开放的特殊移动。
6. 动画、粒子、音效和相机反馈。

关键对象：

- `Hero_Hornet.prefab`
- `InputHandler.cs`
- `HeroActions.cs`
- `HeroController.cs`
- `HeroControllerStates.cs`
- `HeroAnimationController.cs`
- Rigidbody2D、Collider2D、Animator 和 HeroBox

每个动作都画同一条链：

```text
输入
  -> 是否允许动作
  -> 状态切换
  -> 速度/力/碰撞变化
  -> 动画
  -> 音效/粒子/相机反馈
  -> 退出条件
```

实践任务：

- 在 `LearningLab` 独立实现走、跳、落地和一个攻击动作。
- 用帧步进记录跳跃开始、最高点、下落和落地时的关键变量。

完成标准：

- 能解释“表现状态”和“物理状态”何时一致、何时分离。
- 能修改一个移动参数并提前预测手感变化。

### 阶段 6：攻击、受伤与一个敌人（第 9～10 周）

先研究一种基础攻击和一种简单敌人，不研究所有武器、工具和 Crest 分支。

关键代码：

- `HitInstance`
- `DamageEnemies`
- `DamageHero`
- `HealthManager`
- `Recoil`
- 攻击碰撞盒、受击框、无敌时间、死亡效果
- 选定敌人的 PlayMaker FSM 或行为脚本

推荐样本：

- `MossBone Fly`：适合观察简单移动、检测和攻击。
- `Bone Thumper`：适合观察教程触发、场景封锁和战斗结束事件。

实践任务：

- 画出 Hornet 攻击敌人和敌人攻击 Hornet 的两条对称链路。
- 修改伤害、击退或无敌时间中的一个参数，预测并验证结果。
- 在 `LearningLab` 复现一个具有巡逻、发现、攻击、受伤和死亡状态的简化敌人。

完成标准：

- 能定位一次“命中了但没扣血”或“扣血了但没反馈”的断点处于哪一层。

### 阶段 7：教程、交互和场景状态（第 11 周）

研究内容：

- 教学触发器和提示。
- 可破坏植被、障碍、机关、宝箱和 Song Gate。
- 敌人封锁、战斗完成后解锁。
- `PlayerData`、场景布尔值、一次性事件和重新进入场景后的恢复。
- Music Region、Audio Snapshot Region 与环境音循环。

实践任务：

- 选一个一次性事件，记录首次进入、死亡重生、离开再进入三种情况下的状态。
- 复现“进入区域 -> 锁门 -> 战斗 -> 解锁 -> 保存完成状态”。

完成标准：

- 能区分临时场景状态、当前存档状态和全局持久状态。

### 阶段 8：切场景、重生和存档（第 12 周）

研究路线：

```text
Tut_01 -> Tut_01b -> Tut_02
```

关键代码：

- `TransitionPoint`
- `SceneLoad`
- `GameManager`
- `RespawnMarker`
- `HazardRespawnMarker`
- `PlayerData`
- 场景数据保存与恢复

实践任务：

- 追踪正常过门、掉入危险、角色死亡、退出重进四条流程。
- 记录切场景前保存的数据和新场景恢复的数据。
- 在 `LearningLab` 制作两个小场景，支持双向出口、出生点和一个持久开关。

完成标准：

- 能解释角色为何出现在正确入口，以及相机、朝向、状态和音频如何恢复。

### 阶段 9：首场景毕业项目（第 13～14 周）

制作一个不复制商业素材的“小型 Tut_01”：

- 3～5 个相连房间。
- 走、跳、基础攻击。
- 一个简单敌人和一个教学战斗。
- 相机锁区、危险重生和场景出口。
- 背景/中景/前景、粒子和环境音。
- 一个一次性机关和持久状态。
- 可从启动场景进入，并能保存后重新恢复。

毕业验收：

- 能现场画出从输入到画面的主要系统关系。
- 能在 30 分钟内定位一个故意制造的移动、渲染、战斗或切场景问题。
- 能指出自己的实现与原工程设计之间至少三处差异及其取舍。
- 能使用同一模板开始分析 `Tut_01b`，无需重新发明学习方法。

### 阶段 10：扩展到整个项目（第 15 周起）

首场景完成后，按“系统增量”而不是“场景编号”推进：

1. `Tut_01b`、`Tut_02`：补充新交互和场景连接。
2. 一个普通区域：学习地图、Bench、商店、NPC、任务和区域音频。
3. 一个 Boss：学习阶段状态机、招式调度、竞技场和演出。
4. Crest、工具、丝、能力和装备系统。
5. 完整 UI、本地化、存档升级和平台输入。
6. Addressables、对象池、性能、内存和加载优化。

每遇到新场景，只记录“相较已学系统新增了什么”。不要重复分析已经掌握的通用对象。

## 5. 每周安排模板

推荐将每周 8～10 小时分成四次：

| 次数 | 时长 | 内容 |
| --- | ---: | --- |
| 第 1 次 | 2 小时 | 运行观察、提出问题、画初步流程 |
| 第 2 次 | 2～3 小时 | Hierarchy、Inspector、Prefab 和资源定位 |
| 第 3 次 | 2～3 小时 | 代码/FSM 调用链追踪与单变量实验 |
| 第 4 次 | 2 小时 | `LearningLab` 复现、总结和验收 |

单次学习记录模板：

```text
本次问题：
运行现象：
入口对象/组件：
关键参数：
调用链：
我的预测：
实验结果：
仍不确定：
可复用结论：
```
